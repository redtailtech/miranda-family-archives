# shadcn/ui Adoption & Delete Modals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt shadcn/ui primitives themed to the existing warm archival identity, and replace every native `confirm()` with proper in-page dialogs — eliminating the browser-suppressed-dialog failure class that made Delete appear broken.

**Architecture:** shadcn init on Tailwind 4 with its semantic tokens (`--primary`, `--destructive`, `--border`, …) mapped onto the existing palette (`paper`/`ink`/`amber`/`sepia`/`line`/brick red) so the visual identity is unchanged. A small `ConfirmProvider` exposes a promise-based `confirm(opts): Promise<boolean>` backed by a shadcn `AlertDialog` — a uniform drop-in for all six `confirm()` call sites, including the uploader's async duplicate loop. Form/tab/menu primitives are then adopted where they reduce bespoke code, never as a rewrite.

**Tech Stack:** shadcn/ui (Radix primitives + generated components in `components/ui/`), existing Tailwind 4 setup. New npm deps: only what `shadcn add` pulls (radix packages, class-variance-authority, clsx, tailwind-merge, lucide-react).

**Spec:** user-approved design in-conversation (2026-08-27): targeted adoption + modal sweep; bug context — server delete path verified working live; report's root cause = native `confirm()` suppressible via the browser's "prevent additional dialogs" checkbox, which makes the button silently no-op.
